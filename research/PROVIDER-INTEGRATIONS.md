# Provider integration boundaries

Reviewed 2026-10-01 for [Verify DeepSeek, Jev, Laya, and Von integration boundaries](https://github.com/taufiq0205/custom-bot/issues/9). Documentation/source inspection only: no installations, model downloads, API calls, performance tests, or license audit. Laya source revision `6d942c92081fbc139e736bbd9ac0023223c29b7f`; Von `99ffb2adb5663b848f3632d8d447b73bd449889d`. Linked upstream branches and hosted API documentation can change.

## Contracts

| Provider | Purpose and HTTP contract | Authentication and output |
|---|---|---|
| DeepSeek | Text generation: `POST https://api.deepseek.com/chat/completions`, JSON `model`, `messages`, optional streaming. Current documented names are `deepseek-flash` and `deepseek-v4-pro`; select explicitly rather than assume older aliases. | Bearer API key; read `choices[].message.content`, `finish_reason`, served model, and usage. Streaming uses SSE deltas. [First call](https://api-docs.deepseek.com/), [API](https://api-docs.deepseek.com/api/create-chat-completion/) |
| Official TypeSafe Jev | Typed decisions: `POST https://api.typesafe.ai/v1/systemone`, JSON `model`, `state` (string/object/array), named `questions`. `choice` uses described options, `score` ordered criteria, `noul` a yes/no condition. | Bearer TypeSafe key, server-side `TYPESAFE_API_KEY`. Answers retain question names: choice/confidence/probabilities, score/legend/probabilities/confidence, or noul probability; response includes model and usage. [Official quickstart](https://docs.typesafe.ai/introduction/quickstart), [API](https://docs.typesafe.ai/api) |
| Laya | Local decision engine; self-hosted `POST /v1/systemone` implements Jev-shaped questions/answers. Its checkpoint names differ: `english`, `multilingual`, `typed-decisions`; routing may otherwise auto-select. | Set `LAYA_API_KEY` to require Bearer authentication. Without it the server is unauthenticated. Local extras and routing metadata are provider-specific. [Source README](https://github.com/NandhaKishorM/laya#self-hosting-http-server-jev-compatible), [server](https://github.com/NandhaKishorM/laya/blob/main/laya/serve.py) |
| Von | Local decision engine, `von serve` exposes `POST /v1/systemone`; documented Jev-compatible protocol, separate Von model identifiers. | `VON_API_KEY` enables Bearer authentication. Overflow can be refused with HTTP 422 or reported as truncation. [Source README](https://github.com/wfzyx/von#wire-protocol) |

Jev, Laya, and Von select/score bounded answers; they do **not** replace DeepSeek for conversational reply generation or open-ended memory extraction. Jev's own documented limits include literal interpretation, arithmetic/date comparisons, adversarial input, irrelevant context, and generation. Keep exact calculations and authorization in code. [Jev limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13), [Laya model card](https://huggingface.co/convaiinnovations/laya), [Von model card](https://huggingface.co/wfzyx/von)

DeepSeek JSON mode requires an explicit JSON instruction and adequate output budget; empty output remains documented. JSON syntax does not establish application schema correctness. Validate tool arguments and completion status before executing actions. [JSON mode](https://api-docs.deepseek.com/guides/json_mode/), [API](https://api-docs.deepseek.com/api/create-chat-completion/)

## Local deployment and artifacts

| Engine | Runtime, artifacts, license, and limits |
|---|---|
| Laya | Python >=3.10; PyTorch/Transformers/Hub runtime, `laya[serve]` adds HTTP serving. Public downloadable checkpoints: English 421M/512-token context, multilingual 322M/default 1024/up to 8192 with explicit configuration, typed-decisions 421M/1024. Model family is labelled Apache-2.0; preserve notices and pin each checkpoint revision. [README](https://github.com/NandhaKishorM/laya#installation), [family card](https://huggingface.co/convaiinnovations/laya), [multilingual card](https://huggingface.co/convaiinnovations/laya-multilingual) |
| Von | Python >=3.12; Torch, Transformers, FastAPI/Uvicorn; optional OpenVINO. Downloadable `wfzyx/von` checkpoint has 395M parameters, 8192-token context, 1.5GB fp32 backbone; complete download documented around 3GB. Backbone, scoring head, tokenizer, and calibration file are required. Code/model labelled Apache-2.0. English-only; domain-specific errors and poor transfer of calibration are documented. [Runtime manifest](https://github.com/wfzyx/von/blob/master/pyproject.toml), [README](https://github.com/wfzyx/von), [weights/card](https://huggingface.co/wfzyx/von) |

Laya's CPU Docker quickstart requests 8GB RAM/10GB disk, persists checkpoints in a named cache volume, supports offline cached inference, and can serve the HTTP API. NVIDIA requires a compatible driver/toolkit and separate CUDA configuration; health must report the actual checkpoint device because CPU fallback is possible. [Docker guide](https://github.com/NandhaKishorM/laya/blob/main/docs/docker.md)

For this arm64 Mac, Laya documents a native ARM64 Linux CPU build; Apple MPS requires native macOS PyTorch, outside its containers. Von documents native MPS but its published CPU/OpenVINO image is **linux/amd64**: do not assume an ARM64-native image or emulated performance. Prefer optional authenticated host inference services if Apple GPU acceleration is wanted, with the app/database staying in Docker. CPU-only container inference remains a separate measured option. This is a deployment recommendation, not tested compatibility. [Laya platforms](https://github.com/NandhaKishorM/laya/blob/main/docs/docker-platforms.md), [Von images](https://github.com/wfzyx/von#cli)

Docker's `--gpus` Desktop passthrough documentation applies to Windows/WSL2, not Apple MPS. Docker Model Runner offers other acceleration routes, but the inspected projects do not document using it for these custom decision encoders. [Docker GPU support](https://docs.docker.com/desktop/features/gpu/)

## Smallest boundary and acceptance implications

Recommendation: keep **generation**, **typed decisions**, and **retrieval** separate. One server-side decision HTTP helper can send the common `state/questions` shape to a selected Jev/Laya/Von URL, with provider-specific model/auth configuration and validated responses. Keep DeepSeek generation on its chat endpoint; do not add an agent framework or generic provider plugin system for these four providers.

- Same wire shape does not imply equivalent decisions or interchangeable confidence. Evaluate the same held-out business cases separately per engine/version/question type/language. Von's default Noul `band` transforms probabilities to force them outside its abstention band; use `VON_NOUL_DECISION=raw` if application thresholds require posterior probabilities, then validate those thresholds. [Von calibration](https://huggingface.co/wfzyx/von#calibration)
- Reject or explicitly handle oversized inputs. Laya can silently truncate ordinary predictions; Von defaults to middle truncation. Keep retrieved state small and inspect provider overflow metadata. [Laya long documents](https://github.com/NandhaKishorM/laya#long-documents-predict_long), [Von protocol](https://github.com/wfzyx/von#wire-protocol)
- No reusable retrieval-embedding endpoint was established in the inspected DeepSeek/TypeSafe API documentation or Laya/Von public decision contracts. Their internal encoders are not proof of a supported retrieval embedding API. Choose embeddings separately, or explicitly decide lexical retrieval for the first pilot. [DeepSeek API](https://api-docs.deepseek.com/api/create-chat-completion/), [TypeSafe API](https://docs.typesafe.ai/api), [Laya server](https://github.com/NandhaKishorM/laya/blob/main/laya/serve.py), [Von protocol](https://github.com/wfzyx/von#wire-protocol)
- Cloud access remains optional. Per the human decision, local-to-cloud fallback requires explicit permission for that business before transferring customer text; absent permission, fail safely into human handling or an identified simulation. Without DeepSeek credentials, these local decision engines cannot provide real generated replies.

Before live pilot: verify API account access/current model IDs, pinned artifact completeness/licenses, host RAM and actual device, cold-start/cache/offline behavior, timeouts/auth/overflow, quality and confidence on relevant languages, business isolation, and the fallback permission boundary. Prices and benchmark marketing are not pilot evidence. Embedding choice and numeric quality/latency gates remain decisions for the Docker/pilot ticket.
